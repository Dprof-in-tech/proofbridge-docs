Each chain runs the same set of contracts. The two escrows hold the
traders' funds; the rest check signatures and proofs, record events, and
handle the paths a trade takes when it doesn't settle normally.

## What each contract does

| Contract | Role |
| --- | --- |
| `AdManager` | maker escrow: ads, liquidity, locks, the co-signed payout to the bridger, cancels and disputes. Its clock decides how a trade ends. |
| `OrderPortal` | bridger escrow: orders and deposits, the co-signed payout to the maker. It follows the outcome the `AdManager` proves. |
| `MerkleManager` | the append-only Merkle Mountain Range of trade events on this chain |
| `Verifier` | checks the zero-knowledge proof of an event on the other chain |
| `CounterpartyVerifier` | checks both traders' combined BLS co-signature at payout |
| `BLSKeyRegistry` | each wallet's settlement keys, with proof of possession |
| `RootAnchor` | the other chain's Merkle roots, used by cancels, forfeits and disputes |
| `DisputeManager` | dispute filing, bonds and rulings. It never moves escrow funds. |
| `Registrar` | registration of a key by proof from the account's home chain. Deployed, not active yet. |
| `wNativeToken` | wrapped native token for native-asset ads and dispute bonds |

On Ethereum, a few more deployments support these: `ProofBridgeUtils`
(shared order and fee logic, a linked library), `Poseidon2Yul` (the
hash the Merkle tree uses), `SCL_EIP6565` (ed25519 verification, so a
Stellar wallet's signature can be checked on Ethereum), and the agent
contracts (`AgentPolicy`, `AgentPolicyCodec`, `CustodyAccountFactory`).
On Stellar, agent accounts are deployed per maker from a published wasm
hash.

<Note>
The contracts have not been audited yet. An audit is planned for T3,
backed by the Stellar Community Fund.
</Note>
